# AstrBot 海龟汤推理游戏插件

一个为 AstrBot 开发的 AI 海龟汤推理游戏插件，通过调用 AstrBot 的 LLM 服务商实现自动生成谜题、接收用户提问、智能判断是否猜中故事等功能。

## 🌟 插件亮点

- ✅ **功能齐全**：支持游戏创建、智能问答、完整推理验证、提示引导、题库管理等完整流程
- 🌐 **网络题库支持**：已爬取近 **300 道**高质量海龟汤题面，覆盖多种题材与风格
- 🧠 **智能提示系统**：结合全部提问记录生成方向提示，基于 allow_list 限制名词，引导玩家理清思路


## 🎮 功能特性

- **智能谜题来源** - 支持网络题库、本地存储库与 LLM 现场生成，可通过策略设置优先级
- **自动生成与存储** - 在指定时间段自动生成新故事并持久化存储备用题库
- **难度与提问/提示限制** - 简单/普通/困难/666开挂了四种难度，对应不同的提问次数与提示次数限制
- **智能问答系统** - 判断用户提问并回复“是/否/是也不是/不重要”，可选用 LLM（默认）或 [Jev](https://jevmodel.org/zh/docs/) 决策模型
- **验证系统** - 使用 LLM 验证用户提交的完整推理结果
- **提示系统** - 使用 LLM 根据问答历史生成方向性提示
- **题库使用记录** - 记录题目使用情况，可查看并重置
- **会话控制与超时机制** - 每个群一次仅允许一个游戏，且游戏超时自动结束
- **管理员功能** - 强制结束、备用故事管理与题库管理等实用指令
- **用户友好界面** - 清晰的状态显示、次数限制提示和操作指引

## 📋 使用指令

### 基础指令

- `/汤` - 开始海龟汤游戏
- `/查看` - 查看当前已提问的问题及回答
- `/提示` - 获取方向性提示（参考当前所有提问与回答，有次数限制）
- `/验证 <推理内容>` - 验证用户对完整故事的推理，如果超过则结束游戏（有次数限制）
- `/揭晓` - 查看完整故事并结束游戏
- `/汤难度 <简单/普通/困难/666开挂了>` - 设置游戏难度（默认普通）
- `/汤状态` - 查看当前游戏状态
- `/备用状态` - 查看备用故事存储库状态
- `/汤配置` - 查看当前插件配置

### 管理员指令

- `/强制结束` - 强制结束当前游戏（不会告知完整故事）
- `/备用开始` - 手动开始生成备用故事
- `/备用结束` - 停止生成备用故事
- `/重置题库` - 重置网络题库和本地存储库的使用记录
- `/题库详情` - 查看题库使用情况与已用索引

## 🎯 游戏流程

1. **开始游戏** - 用户发送 `/汤`
2. **获取谜题** - 按策略从网络题库、本地存储库或 LLM 生成
3. **公布题面** - 题面发布到群聊并启动会话控制
4. **用户互动**
   - @机器人 + 任意陈述/问题（AI 回复：是、否、是也不是、不重要）
   - `/验证 <推理内容>` 验证完整推理过程
   - `/提示` 获取方向性提示（结合当前所有问答记录，有次数限制）
   - `/查看` 查看当前已提问的问题及回答
5. **游戏结束** - 用户输入 `/揭晓` 或验证成功时结束游戏

## 🔍 验证系统

用户可以通过 `/验证` 指令验证自己的完整推理过程：

> 除「简单」难度外，在提问次数用完前 `/验证` 指令最多可使用两次，用尽后会提示"已经没有验证次数了"。提问次数用完后仍可再次获得两次验证机会。提示功能也有相应的次数限制，不同难度对应不同的提示次数。

- **完全还原**：推理与标准答案高度一致，包括核心逻辑与关键细节
- **核心推理正确**：推理的大方向或关键反转已覆盖，但部分细节有出入
- **部分正确**：理解了部分情节或动机，但因果链不完整
- **基本不符**：推理与真相严重不符

在 `简单` 难度下，"完全还原"或"核心推理正确"均视为猜中；其他难度需要达到"完全还原"才算猜中。

## 💡 提示系统

用户可以通过 `/提示` 指令获取方向性提示：

> 不同难度对应不同的提示次数限制：
> - **简单**：10 次提示
> - **普通**：5 次提示  
> - **困难**：1 次提示
> - **666开挂了**：无提示

提示系统会根据玩家此前的所有提问记录和已给出的提示，结合题面构建允许名词列表（allow_list），在此基础上生成不重复的方向性引导，帮助玩家调整思考方向。提示内容不会包含故事情节、动机、行为或结局的具体信息，仅围绕提问角度、方向、范围进行结构性引导，并以“关注【维度】：动词+对象/变量”的格式给出。提示次数用完后将无法继续使用。

## 🔧 技术特性

- **LLM 集成** - 使用 AstrBot 的 Provider 接口调用大语言模型，支持生成、判断和提示功能
- **双 LLM 分离** - 支持分别配置生成谜题和判断问答/提示的 LLM 提供商（配置页下拉选择，不用手填服务商 ID）
- **Jev 决策后端（可选）** - 问答判断可改用 Jev 决策模型做类型化判断：更便宜（只计输入 token）、更快（约 2~4 秒），并且它给出的是概率而不是一段需要解析的文字
- **题库与存储** - 网络题库与本地存储库结合，支持自动生成、持久化和使用记录
- **会话管理** - 基于群聊的会话控制，支持多用户参与和指令处理
- **验证系统** - 智能验证用户推理的准确性和完整性
- **提示系统** - 基于问答历史生成方向性提示，帮助玩家调整思考方向
- **错误处理** - 完善的异常处理和边界情况处理
- **用户体验优化** - 智能提示、状态反馈和操作引导
- **状态持久化** - 游戏状态、题库使用记录和提示次数持久化保存

### 支持哪些网关

| 网关 | 接口地址 | 端点路径 | 接口协议 | Key |
|---|---|---|---|---|
| Jev 官方 | `https://jevmodel.org` | `/v1/systemone` | systemone | `sk-` 开头 |
| TypeSafe | `https://api.typesafe.ai` | `/v1/systemone` | systemone | `sk-` 开头 |
| JevTypeSafeAI（第三方代理） | `https://jevtypesafeai.com` | `/api/v1/decide` | systemone | `jv_live_` 开头 |

第三方代理的协议与官方一致，只是路径带 `/api` 前缀——把「端点路径」填成
`/api/v1/decide` 即可。其余网关留空「端点路径」，插件会按「接口协议」自动拼。

不确定配置对不对时，跑一下 `python scripts/probe_jev.py --base-url ... --api-key ...`，
它会告诉你问题出在 Key、余额、路径、模型通道还是上游。

### 走 Jev 决策网关

Jev 的 Key、地址、模型、超时统一由 [astrbot_plugin_jev_gateway](https://github.com/uuutt2023/astrbot_plugin_jev_gateway)
管理。本插件的设置里只填两项——

- **网关代理地址**：如 `http://127.0.0.1:8770`
- **请求协议**：固定三项下拉（SystemOne / OpenAI Decisions / Custom），
  网关里同协议登记多个入口时按优先级和负载均衡挑
- **Jev 提示词**：可自定义问 Jev 的话（大文本框）。留空＝用内置提示词；
  填了就替换判定题的问法，选项集不受影响

协议翻译（SystemOne ⇄ OpenAI Decisions）、重试、30 秒去重缓存、余额追踪都在网关那边，
本插件只管发问题、读答案。换网关时只改网关一处。


> **Docker 里**：容器内的 `127.0.0.1` 指的是容器自己。插件和网关不在同一个容器时，
> 网关要绑 `0.0.0.0`，这里填容器名（如 `http://astrbot:8770`）。

## 🚀 安装使用

1. 将插件放置在 `AstrBot/data/plugins/` 目录下
2. 在 AstrBot WebUI 的插件管理处启用插件
3. 在插件配置页面下拉选择 LLM 提供商，并设置其他参数
4. 确保已配置 LLM 服务商（推荐单独配置判断问答的 LLM 服务商以获得更好的提示效果）
5. 在群聊中使用 `/汤` 开始游戏

## ⚙️ 配置说明

插件支持以下配置项：

- **生成谜题的 LLM 服务商** - 下拉选择（列表来自 AstrBot 已配置的对话模型），留空使用默认
- **判断问答的 LLM 服务商** - 下拉选择（列表来自 AstrBot 已配置的对话模型），留空使用默认
- **游戏超时时间** - 游戏超时时间（秒）
- **存储库最大容量** - 存储库最多保存多少个备用故事（默认 50）
- **自动生成开始时间** - 每天自动生成备用故事的开始时间（小时，24 小时制，默认 3）
- **自动生成结束时间** - 每天自动生成备用故事的结束时间（小时，24 小时制，默认 6）
- **谜题来源策略** - `network_first`（网络题库→本地存储库→LLM）、`ai_first`（本地存储库→网络题库→LLM）、`random` 随机选择
- **判断问答的后端** - `llm`（默认，行为与原来完全一致）、`jev`（只用 Jev 决策模型）、`hybrid`（Jev 先判，置信度不足再回退 LLM）
- **Jev 判断**（仅 `jev` / `hybrid` 生效） - 启用开关、API Key、接口地址、**接口协议**、模型名、超时、重试、置信度门控方式、**提示词语言**、**显示相关性百分比**、采信阈值、上下文长度上限、带入的历史轮数
- **接口协议** - `systemone`（默认，POST `/v1/systemone`，官方 Jev / TypeSafe / StartLux）或 `decisions`（POST `/v1/decisions`，OpenAI Decisions 协议，部分中转站用这个端点）；两者请求体结构不同，插件内部自动翻译

配置修改后需要重载插件生效。

### 🧠 Jev 决策后端

玩家每提一个问题，插件就要判断一次该回“是/否/是也不是/不重要”。这个判断本质上
是一次**四选一分类**，不需要生成任何文字——正好是 [Jev](https://jevmodel.org/zh/docs/)
决策模型擅长的类型化判断：

| 后端 | 行为 | 适合谁 |
|---|---|---|
| `llm`（默认） | 维持原样，调用 LLM 生成判断再解析 | 不想改现状的用户 |
| `jev` | 只用 Jev 判断，不调用大模型 | 想要更快、更便宜，且已备好 Jev API Key |
| `hybrid` | Jev 先判，把握不大时才调用 LLM 复核 | 想省钱又不愿意让 Jev 独断 |

Jev 的两个特点让它比 LLM 更适合做这件事：

- **只对输入 token 计费，输出免费**——判断一次大约 100 个输入 token；
- **上游失败不计费**，可以安全重试。

插件的失败处理是「Jev 永远不能把游戏搞坏」：未启用、未配置 Key、超时、上游故障、
返回结构不合法……任何一种情况都会**自动回退 LLM**，玩家永远拿得到四档判定之一。

**配置步骤**

1. 在 [Jev 控制台](https://jevmodel.org/zh/docs/)创建 API Key（`sk-` 开头）；
2. 插件配置页把「判断问答的后端」改成 `jev` 或 `hybrid`；
3. 在「Jev 判断」分组里填入 API Key，保持接口地址为 `https://jevmodel.org`。

「置信度门控方式」有两种口径：按阈值（可复现，默认）与按概率抽样（平滑）。
抽样口径下，Jev 对自己这一档越没把握，调用 LLM 复核的频率就越高——
成本随不确定性平滑上升，抽样值会写进日志便于复盘。

### 🧩 判题是怎么问 Jev 的

判定请求长这样（`state` 用结构化对象，Jev 文档允许 `string / object / array`）：

```json
{
  "model": "jev-latest",
  "state": {
    "汤面": "深夜停电，男主人死在上锁的浴室里。",
    "真相": "他滑倒撞到头后跌进浴缸溺水，锁是他自己装上去的。",
    "历史问答": ["「他是不是自缢」→ 否"],
    "玩家提问": "他是不是滑倒的"
  },
  "questions": {
    "verdict": {
      "type": "choice",
      "instructions": "这是一个海龟汤（情境推理）游戏……",
      "criteria": { "是": "……", "否": "……", "无关": "……" }
    }
  }
}
```

几个刻意的设计：

- **只有三档：是 / 否 / 无关**（对齐 Situation-Puzzle）。原先的「是也不是」
  去掉了——那种「说对一半」的提问现在表现为**置信度不足**：分布摊在「是」和
  「否」之间，被置信度门控拦下交回 LLM 复核（`hybrid` 模式即是如此）。
- **选项标签就是玩家看到的那三个字**——Jev 返回 `否`，就显示 `否`，中间不
  再做一层映射，也就不会映射错。
- **提示词跟随题目语言**——中文题目用中文 criteria，英文题目用英文；
  「提示词语言」配置可以固定口径（默认自动判断）。
- **历史问答带上当时的判定**（`「他是不是自缢」→ 否`），这样"他刚刚说的那个"
  这类指代才有落点。参考项目的评测结论是：上下文只在真歧义时改变结果，
  不会引入回归。
- **判定程序写进 instructions**——「否」和「无关」最容易混，所以顺序写死：
  先在真相里找事实 → 找到就答 是/否（哪怕只是顺带提到）→ 真相**明确排除**才答 否
  → 真相**完全沉默**才答 无关；历史问答只用来消解「他」「那个」这类指代，
  不能当证据。
- **缺概率算协议错误**——响应必须带合法选项和对应概率，缺概率不默认为 0，
  而是回退 LLM。
- **提示词有版本号**（`v1-2026-11-soupai`），改提示词就要升版本，日志和
  `/汤配置` 里都能看到当次用的是哪套。

想验证判定质量，可以用仓库里的离线评测脚本（需要真实 Jev API Key）：

```bash
export JEVMODEL_API_KEY=sk-xxxx
python scripts/eval_judgment.py              # 跑固定用例，输出准确率
python scripts/eval_judgment.py --compare    # 额外对比带/不带历史问答
```

改完提示词先跑一遍它，确认没退化再发布。

### 📊 相关性百分比

Jev 不只给结论，还给出它对这一档的把握（概率）。打开「显示相关性百分比」开关后，
判定后面会附带这个百分比：

```
是（3/10，相关性 88%）
```

它是给玩家的提示——**这次提问问得有多准**。几个细节：

- 只有 **Jev 判定**才有概率，走 LLM 判断时不显示百分比；
- 百分比只出现在回复里，问答历史仍然只记干净的「是/否」，不会污染后续的提示词；
- 概率极低（不足 1%）时显示 `<1%`，而不是四舍五入成误导性的 `0%`。

## 📝 开发说明

本插件基于 AstrBot 插件开发框架构建，使用了以下核心功能：

- `@register` 装饰器注册插件
- `@filter.command` 注册指令处理器
- `session_waiter` 实现会话控制
- `async def generate_hint(puzzle, true_answer, qa_history, hint_history, allow_list)` 实现提示生成功能
- `self.context.get_using_provider()` 调用默认 LLM 服务
- `self.context.get_provider_by_id()` 调用指定的 LLM 服务商
- `self.game_state.start_game()` 支持提示次数初始化
- `core/jev_transport.py` Jev 传输层：本地预检请求体、幂等键、错误码映射、额度统计
- `core/jev_judge.py` Jev 判定层：state 构造、四选一映射、置信度门控（纯逻辑，不依赖 astrbot）
- `self.judge_question()` 按 `judge_backend` 在 LLM 与 Jev 之间分发，任何 Jev 异常都回退 LLM
